ReLimiter — справочник по возможностям
==================================

Основные функции
-------------

Ограничение FPS
  Ползунок 0-500. Быстрые кнопки: 30, 60, 120, 240, лимит Reflex.
  Формула лимита Reflex: fps = refresh - (refresh^2 / 4096), с округлением вниз.
  Пример: 165 Гц -> 165 - (27225/4096) = 165 - 6.64 = 158.

Переопределение VSync
  Игра (сквозной режим), Вкл (SyncInterval=1), Выкл (SyncInterval=0 + ALLOW_TEARING).
  Хук IDXGISwapChain::Present. Разрывы определяются автоматически через IDXGIFactory5.
  Также применяется в прокси-хуке Present у Streamline.

Оптимизация pacing для серии 5XXX
  Хук IDXGISwapChain2::SetMaximumFrameLatency, переопределяет значение на 1.
  Только для waitable-swapchain. Исходное значение игры сохраняется и восстанавливается.
  Рассчитано на GPU NVIDIA 50-й серии с поддержкой flip metering.

Режим FG
  Автоопределение DLSS FG, FSR FG, Smooth Motion по загруженным DLL.
  Ручное переопределение: Выкл, 2x, 3x, 4x.
  Целевой FPS делится на множитель для получения реальной частоты рендеринга.

Переопределение Boost
  Игра (сквозной режим), Вкл (принудительный boost), Выкл (принудительно без boost).
  Управляет Reflex Low Latency Boost (управление частотами GPU).

Пресеты pacing
  Native Pacing    — SIM_START, без лимита очереди. Минимальная задержка.
  Marker Low Lat   — маркеры Reflex, не более 1 кадра в очереди.
  Balanced         — маркеры Reflex, не более 2 кадров в очереди.
  Stability        — маркеры Reflex, не более 3 кадров в очереди.
  SL Proxy         — pacing генерируемых кадров через прокси Streamline.
  Custom           — ручное управление всеми подпараметрами.


Адаптивные функции, уникальные для UL
------------------------------

Эти функции есть только в ReLimiter. Ни Special K, ни Display
Commander их не реализуют.

1. Предиктивная задержка сна
   Планирование пробуждения с учётом GPU. Хранит историю из 8 замеров времени GPU
   со взвешенным усреднением (4x/3x/2x/1x). Определяет восходящие тренды
   (3+ кадра роста подряд) и смещает прогноз вверх. Адаптивный запас безопасности:
   старт с 500 мкс, +50 мкс за промах, -10 мкс за 30 стабильных кадров,
   ограничение 200–2000 мкс. Активно только при упоре в GPU.
   Предиктивный интервал может только сокращать базовый.

2. Фазо-заблокированная сетка таймингов
   target[k] = epoch + k * interval. Накопления дрейфа нет. Опоздавшие кадры
   подтягиваются вперёд. Использует CREATE_WAITABLE_TIMER_HIGH_RESOLUTION + активное
   ожидание на хвосте. ZwSetTimerResolution для максимальной точности таймера ядра.

3. Контур обратной связи Present-to-Present
   Коррекция с замкнутым контуром. Накапливает ошибку P2P за 30 кадров.
   Сдвигает интервал на +/-1 мкс за окно. Мёртвая зона +/-1 мкс.
   Общий предел +/-8 мкс. Активно только без FG. Сброс при смене лимита FPS.

4. Автоматический выбор точки принудительного применения
   Нагрузка GPU > 85% -> SIM_START (минимальная задержка).
   Нагрузка GPU < 65% -> PRESENT_FINISH (лучший pacing).
   Гистерезис 65–85% предотвращает «дёрганье» между режимами.

5. Определение давления очереди
   Следит за временем очереди рендеринга ОС через GetLatency. Если среднее время
   очереди > 1.5x целевого интервала, добавляет 4 мкс к интервалу сна,
   снижая нагрузку проактивно.

6. Адаптивный pacing для DLSS FG
   Измеряет фактические накладные расходы FG (от конца рендеринга GPU до конца
   present) через GetLatency. Сглаживание EMA (alpha=0.1). Заменяет статическую
   прибавку +24 мкс. Ограничение 4–60 мкс.

7. Гибридное ожидание очереди
   Две фазы: сон на waitable-таймере (~0.5 мс), затем активное ожидание последних <1 мс.
   Таймаут 50 мс. Экономит CPU по сравнению с чистым спин-ожиданием в SK и DC.

8. Прогрев по времени
   Двухсекундный прогрев от первого present по настенным часам. Одинаков
   для любых частот кадров (прогрев по числу кадров — это 10 с при 30 FPS,
   но всего 1.25 с при 240 FPS).

9. Корректное восстановление Reflex
   При установке хука сохраняет параметры SetSleepMode игры. Восстанавливает
   при завершении. Если игра ни разу не вызывала SetSleepMode — аккуратно
   отключает Reflex.

10. Учёт VRR / GSync
    Потолок = 3600 * hz / (hz + 3600). Запас безопасности 0.5%. Ограничивает
    интервал так, чтобы лимитер не выходил за окно VRR. Кешируется на 2 с.
    Отключается при выключенном VSync.

11. Адаптивная подстройка интервала
    Нагрузка GPU < 70%: -3 мкс (ужесточение). Нагрузка GPU > 90%: до +4 мкс (запас).
    Срез драйвера: всегда -2 мкс для компенсации систематического перебега.

12. Блокировка flip metering
    Хук nvapi_QueryInterface. Блокирует ординал 0xF3148C42 (SetFlipConfig),
    возвращая nullptr. Исключение: Smooth Motion (flip metering ему нужен).
    Собственные запросы UL идут через оригинальный указатель QI.
    Активно всегда, без переключателя.


Конвейер вычисления интервала
-----------------------------

Сырой интервал (из fps_limit / делителя FG)
  -> ограничение по полу VRR
  -> прибавка FG (адаптивная или статические +24 мкс)
  -> давление очереди (+4 мкс при срабатывании)
  -> коррекция запаса GPU (-3 мкс до +4 мкс)
  -> коррекция обратной связи P2P (-8 мкс до +8 мкс)
  -> срез драйвера (-2 мкс)
  -> предиктивный сон (может только сократить)
  = Итоговый minimumIntervalUs, отправляемый драйверу


Сводка по хукам Reflex
-------------------

SetSleepMode  — Перехватывается. Параметры игры сохраняются. Режимом сна управляет UL.
Sleep         — Перехватывается. UL вызывает Sleep по собственному расписанию.
SetMarker     — Перехватывается. RTSS отфильтровывается. INPUT_SAMPLE переставляется.
                Метки времени в кольцевом буфере на 64 слота. Дедупликация по кадру.
GetLatency    — Не хукается. Вызывается напрямую для адаптивных функций.
QueryInterface — Хукается. Блокирует flip metering (SetFlipConfig).


Smooth Motion
-------------

Определяется по NvPresent64.dll. Это НЕ то же самое, что генерация кадров DLSS.
Когда активен: обход Reflex Sleep, только тайминг-pacing, блокировка flip metering
отключена, FPS/Native в OSD меняются местами.


Элементы OSD
------------

FPS           Белый    Частота на выходе (включая сгенерированные кадры)
Native FPS    Белый    Реальная частота рендеринга по меткам SIM_START
Frame         Белый    Скользящее среднее времени кадра (окно 64 кадра)
GPU           Циан     Активное время рендеринга GPU из GetLatency
Render Lat    Циан     От sim-start до конца рендеринга GPU
Present Lat   Циан     От начала до конца present
FG            Золотой  Определённая технология FG + множитель
Res           Золотой  Разрешение рендеринга -> вывода с процентом масштаба
Graph         Зелёный  История фреймтайма на 128 замеров, автомасштабирование
