# Install, Update & Orchestration Knowledge

## Update All
- Respects per-game exclusions (Update Inclusion dialog)
- `AnyUpdateAvailable` property drives the purple button state
- Must call `NotifyUpdateButtonChanged()` after any status change
- Cache phase restores saved update statuses from `game_library.json` (`UpdateAvailableSnapshot`)
- `SaveLibrary()` must be called after `CheckForUpdatesAsync` completes
- **Silent auto-updates save the library too** (`AutoUpdateService.SaveLibraryIfUpdated` → `MainViewModel.SaveLibraryAfterUpdates`, queued on the UI thread behind the installs' status changes, once per pass / retry pass). Before Nov 2026 they didn't: a restart within the update-check cooldown restored the old UpdateAvailable snapshot and the next pass installed the same updates again.
- Background scan merge must preserve `UpdateAvailable` (fresh cards always have `Status = Installed`)
- Foreign DLLs silently skipped. DLL override games ARE eligible (resolve via `dllOverrideService`).
- **After batch completion**: must call `NotifyUpdateButtonChanged()` + reset Nexus baselines by name

### Update Status Persistence
- REF/Luma: restore guard `if (status != NotInstalled)` fails during cache phase (detection only on background scan). Fix: remove guard, set unconditionally from snapshot.
- Nexus updates for non-external games: snapshot may not persist if `SaveLibrary()` timing is wrong.
- RDX cooldown blocks re-check: if not saved after first detection, lost on restart.

### Stale Update Indicators
- Luma false update: check must reset cards from `UpdateAvailable` to `Installed` when no update exists.
- Nexus false positives: `updatedAt` changes for any page edit. Reset baseline on button click + install.
- Update exclusion not respected on restore: check exclusion flags before restoring status.
- Nexus badge on uninstalled games: `UpdateBadgeVisibility` requires installed evidence.

## Install Flows

### ReShade
- 3 channels (Stable/Nightly/Legacy/Custom). Per-game override.
- Vulkan games: global layer at `C:\ProgramData\ReShade\` + elevation
- Legacy: on-demand download from manifest URL list
- Custom: per-game picker from `Custom\ReShade\` folder

### RenoDX
- Standard: download addon from wiki snapshot URL, deploy to game folder
- UE-Extended: toggle visible on ALL UE games. Toggle ON uninstalls named mod. No auto-install.
- `nativeHdrGames` supersedes `ueExtendedGames` (both use UE-Extended, native HDR has Set_Path=0)

The record's `AddonFileName` is the addon inside; `FileHash` / `RemoteFileSize` are the zip's, and the update check downloads the zip and compares its SHA-256 (`CheckZipPackageUpdateAsync`). Wiki links ending in .zip land in `SnapshotUrl` (64-bit slot); a 32-bit game with no `SnapshotUrl32` uses it. Not in the folder-move inventory yet.

A file there that RHI didn't place is never replaced. The helper is in `PeHeaderService.RhiToolExes`. In `RenoDXdb.json` since 19 Nov 2026 (zip in `snapshotUrl`); manifest `graphicsApiOverrides` DX11 makes ReShade `dxgi.dll` (RHI detected DX9 and installed `d3d9.dll`). **Launcher settings** (`BatmanAcSetup.Config.cs`, tests `BatmanAcSetupTests`): `[SystemSettings]` `AllowD3D10=False`, `AllowD3D11=True`, `MultisampleMode=1xMSAA`, `PostProcessAAType=0` (FXAA off), `DepthOfField=True` (off skips the colour grade), plus `MaxMultisamples=1` in BmEngine.ini; written into `UserEngine.ini` (the launcher's own file, applied on top) and `BmEngine.ini` in `MyDocuments\WB Games\Batman Arkham City GOTY\BmGame\Config` (MyDocuments: may be OneDrive; PCGW's `%USERPROFILE%\Documents` path is wrong there) by line edits (`SetInSection`, never ParseIni: `[SystemSettingsMobile]` has its own `DepthOfField=FALSE`), one-time `.rhi-backup`, not reverted on uninstall; skipped when the files don't exist yet. **The files are UTF-16 LE with a BOM** (UE3): `ReadWithEncoding` keeps the file's own encoding (the first version saved UTF-8, half the size). ### Engine.ini Deployment
- Auto for UE5 UE-Extended games on install/Update All. **UE4 UE-Extended: Engine.ini HDR keys skipped by default** (no native HDR pipeline). User can still enable manually via cog dialog.
- `ApplyEngineIniHdrSettings`: resolves project name from install path, finds platform subfolder
- Platform folder follows the copy's store (`FindPlatformConfigDir(base, store)`, issue #138; a game played from both stores has both folders): Game Pass (`Xbox`) = WinGDK only, created if missing (never the Steam copy's Windows); other stores = Windows → WindowsNoEditor → WinGDK → create Windows. PCGW `config_path_xbox` (Xbox cards) / `config_path` still win when present. Tests: `EngineIniPlatformFolderTests`.
- **Never use ParseIni/WriteIni** (destroys duplicate keys). Use append-based approach.
- Set read-only after writing. Remove before writing.
- `InstalledModRecord.EngineIniHdr` boolean controls whether it fires (preserved across reinstall).
- `r.LUT.UpdateEveryFrame=1` unconditional for all UE games regardless of version (separate toggle).
- Alternate locations: Documents\My Games, in-game directory `{Root}\{Project}\Saved\Config\`
- Generic "Project" folder: check grandparent if candidate has no matching AppData folder.
- Pipe-separated paths in override for multi-store games.

### Native HDR / UE-Extended reshade.ini — UE4 vs UE5 Differentiation
- `ApplyRenoDxNativeHdrSettings(gameDir, usesSdrPath)`: UE5 gets `Set_Path=0` (native HDR), UE4 gets `Set_Path=1` (SDR upgrade)
- UE4 detection: `card.EngineHint?.Contains("Unreal Engine 4")` — requires accurate `EngineHint` (from auto-detect or `engineHintOverrides` manifest field)
- Only affects FRESH installs — method only adds missing keys, never overwrites existing user values
- Deploy ReShade.ini button callers use default (`usesSdrPath: false`) — safe for already-installed games
- **Record field must reflect skipped deployment**: When Engine.ini HDR is skipped for UE4 games, `InstalledModRecord.EngineIniHdr` must be explicitly set to `false` and saved. Otherwise the cog dialog reads the default (`true`) and shows "On" despite nothing being deployed. Same pattern applies to any conditional feature skip — the record must always reflect the actual deployed state.
- **Use `record` (local variable from `InstallAsync`), NOT `card.InstalledRecord`**: On fresh installs, `card.InstalledRecord` is still null when post-install logic runs — it's only assigned later in the dispatcher. The local `record` variable IS the correct target for modifications. Same issue doesn't affect reinstalls (card already has a record from the previous install).
- **Update All must NOT override user's explicit toggle state for UE4 games**: The UE4 `EngineIniHdr = false` logic only belongs in the fresh install path (`InstallModAsync`). The Update All path must respect the existing record value — if the user manually enabled HDR via cog dialog (`EngineIniHdr = true`), Update All should honour that and deploy HDR keys. Only fresh installs (no previous record) get the UE4 default of "Off".

### engineHintOverrides (Manifest Field)
- Maps game name → full engine hint string (e.g. `"Unreal Engine 4.27.2"`, `"Unreal Engine 5.4.3"`)
- Applied in `BuildCards` + `LoadCacheAndBuildCardsAsync` AFTER auto-detection, BEFORE user badge override
- Priority: user badge override > manifest override > auto-detection
- Use cases: Game Pass games (ACLs prevent version detection), accurate DOF Fix eligibility, UE4 vs UE5 differentiation
- **Engine badge click blocked** when `EngineHint` contains a specific version number (regex `Unreal Engine \d`). Only toggleable when hint is vague "Unreal Engine" or "Unreal Engine 5". Works regardless of version source (manifest override, auto-detection, or user override). Does NOT depend on `ViewModel.Manifest` being loaded — safe during cache phase.
- **Badge visual styling must match click handler**: `DetailPanelBuilder.cs` determines `isClickable` (underline, tooltip, hand cursor) separately from the `EngineBadge_PointerPressed` handler guard. Both use the same regex check. If they disagree, the badge looks clickable but does nothing (confusing UX). The `isClickable` logic: `hasSpecificVersion` (regex) → false. Only vague "Unreal Engine"/"Unreal Engine 5" with a user override makes it clickable again.
- **Stale user EngineVersionOverrides conflict**: If a user previously clicked the badge (setting e.g. `"Palworld": "Unreal Engine 5"` in settings.json) and a manifest `engineHintOverrides` entry is later added for the same game, the stale user override won't fire (guard requires `EngineHint == "Unreal Engine"` which is false after manifest applies). BUT if the user's override was set when no manifest override existed, it persists in settings.json. On the FIRST launch after adding the manifest override, the manifest applies first → user override guard fails → correct behavior. However if somehow the manifest loads AFTER the user override is checked, the stale value could stick. The priority chain (manifest > user override check) protects against this in normal flow.

### renodxIniOverrides
- Manifest field: game → { key: value } for `[renodx]` section
- `forceOverwrite=true` on install (`InstallModAsync`, Nexus install) and the redeploy button; `false` on Update All (only adds missing, keeps user edits). Install forces on purpose since v2.4.0 (`b4cbac4`): keys written by earlier install steps (placeholders, native HDR) blocked the overrides on fresh installs
- Called from `InstallModAsync` and `UpdateAllRenoDxAsync`

### RenoDX [renodx] Key Placeholders
- `ApplyRenodxKeyPlaceholders`: pre-writes empty keys for Unreal/Unity games
- Triggers for `!UseUeExtended` generic UE/Unity games only
- Uninstall cleanup: removes entire `[renodx]` section

### ReLimiter / Display Commander
- Standard addon deployment
- Auto-disable driver FPS cap on install. Delete setting on uninstall.
- **ReLimiter version pin** (⚙ › Version, `MainWindow.Events.Components.FrameLimiters.Version.cs`): per-game `GameNameService.UlPinnedVersion` (`"Game|Store"` → release tag; `Get/SetUlPinnedVersion`, `IsUlPinned`). `UlReleaseService` lists releases (32-bit builds only from v3.3.1) and stages a pinned build in `framelimiter\pinned\<tag>\`. `InstallUlAsync` deploys the pin when set and then **doesn't write `ul_meta.json`** (that file tracks the global latest build). The update check, Update All and the cached update snapshot skip pinned games. A version change on an installed game = `SwitchUlVersionAsync` (binary only: no ini, driver FPS cap or global-setting writes).
- **ReLimiter v4** (Nov 2026, user decisions): v4 ships as a normal `releases/latest`, but only some games get it. Rules are pure in `Services/UlV4Rules.cs` (tests `UlV4RulesTests`): blocked = 32-bit, Vulkan (`RequiresVulkanInstall`), DXVK (incl. the RenoDX Source mod's DXVK proxy), OpenGL, non-NVIDIA (`GpuInfoService.QueryFailed` separates "WMI failed" = Unknown from "no NVIDIA"); allowed with a note = DX9/10/11, API unknown, GPU unknown; **automatic** (update moves the game to v4) = NVIDIA + DX12. Per-game choice `GameNameService.UlMajorChoice` (`"Game|Store"` → `"3"`/`"4"`, absent = Automatic; rename-migrated; Copy Report `ulMajorChoice`); a pin (`UlPinnedVersion`) still wins. DX12 test (`MainViewModel.UlDx12For`, `MainViewModel.ReLimiterV4.cs`): user Rendering API override → manifest `graphicsApiOverrides` → PCGW (lists DX12 + scan has DX12 = yes; lists APIs but no DX12 = no) → scan alone (only DX12 = yes; only older = no) → `ReShade.log` (`UlV4Rules.ApiFromReShadeLog`, checked against ~90 real logs, Nov 2026): (1) ReLimiter's own `[ReLimiter] on_present: captured presenting swapchain ... api=N` line (DX11 / DX12 only; numbers from `ActiveAPI` in ReLimiter's `swapchain_manager.h`: before v3.3.1 None/DX11/DX12/Vulkan/OpenGL = 0-4, from v3.3.1 None/DX9/DX11/DX12/Vulkan/OpenGL = 0-5, version from the log's `Registered add-on "ReLimiter" vX` line; the 4.0.0 test build didn't write it); (2) only `vkCreateInstance` / `vkCreateDevice` = Vulkan (blocks v4 even when the card says DX12, e.g. Ryubing); (3) the device each `Running on` line follows: DX12 if any follows a D3D12 device, else the last one. "Any D3D12 device" is wrong: DX11 games create a D3D12 test device first (ZERO PARADES), DLSS 5 Bridge / GITC Uplift create one in DX11 games after ReShade starts, HSF just before (FFXV; only ReLimiter's line catches that); DX12 games may start with a DX11 splash (Hogwarts Legacy); `D3D11On12CreateDevice` and the D3D11 lines after it count as D3D12 (Nice Day for Fishing, BLACKWOOD). The card's `DetectedApis` are untouched (Luma needs DX11 listed for Unreal). Games that stay on v3 get the newest 3.x tag from `UlReleaseService` (`GetLastV3TagAsync`), staged like a pin (`pinned\<tag>\`), no `ul_meta.json` write. **Installed version = the game's addon FileVersion** (`ReadUlAddonVersion`, cached by size + date; v3.2+ builds have one), not `ul_meta.json`; `CheckUlUpdateAsync` is per game (returns the outdated cards, null = check failed; the caller also clears stale UpdateAvailable) and never moves a game from v4 back to v3 (the ⚙ warns and has Switch to v3). `EnsureUlCachedAsync` re-downloads the cached "latest" file when its version isn't `_latestUlVersion` (v3-only libraries never pre-cache v4). **Major change (v3 ↔ v4) in `InstallUlCoreAsync`** (install, update, Update All, auto-update and the picker all go through it): old ini copied to `relimiter.ini.v{old}-backup`, then a fresh ini with only RHI's lines (`UlV4Rules.BuildFreshIni`: osd_toggle_key, shared_presets, dlss_info_hooks, target_fps), also RE Framework's `_storage_` copy; display mode values kept (`KeepDisplayModeValues`). A fresh v4 install never gets the v3 template (`WriteFreshUlIniIfAbsent`). Backups are removed on uninstall and listed in the folder-move inventory. Picker items once a 4.x release exists: Automatic / v4 (latest, only when allowed) / v3 (final) / tags (v4 tags hidden when blocked); before that the old Latest (auto-update). **Dev test build** (needs `unlock.txt`): `%LocalAppData%\RHI\relimiter-v4-test\relimiter.addon64` is treated as the latest 64-bit release (`ApplyUlDevOverride` sets `_latestUlVersion` from its FileVersion in `FetchLatestUlReleaseInfoAsync`, `CheckUlUpdateAsync` and `LastV3TagInsteadOfLatestAsync`; installs copy it, no pre-cache, no `ul_meta.json` write; the ⚙ says it's on). The last v3 still comes from GitHub. A build newer than the latest release in the download cache (`framelimiter\relimiter.addon64`, v4 testers without unlock.txt, Nov 2026) is kept: `EnsureUlCachedAsync`, the reinstall cache delete and `PreCacheRemoteUlVariantAsync` all check `IsUlCacheNewerThanLatest`; only an older cached build is replaced with the real latest.

### OptiScaler
- Installs as `dxgi.dll`, renames existing ReShade → `ReShade64.dll`
- **Detection must not trust OptiScaler.ini alone** (`OptiScalerService.DetectInstallation`): DLSS Enabler 4.x has OptiScaler built in and writes its own `OptiScaler.ini`. The old fallback (ini present → any DLL with a supported name is OptiScaler) recorded ReShade's `dxgi.dll` as OptiScaler in Townfall (Nov 2026). Now: no fallback when a supported name holds DLSS Enabler (`DlssEnablerService.IsDlssEnablerDll`), and DLLs that report another mod (`OtherProxyProduct`: ReShade, DLSS Enabler, ASI Loader, RTX Encore, UE4SS, Special K, DXVK, dgVoodoo, MFG Unlocker, Display Commander, ENBSeries) are skipped. BuildCards drops existing records like that (`IsMisdetectedRecord`: no OptiScaler install in `rhi_install.txt` + the DLL reports another mod), so custom OptiScaler builds RHI installed are never touched.
- Uninstall: only delete DLSS DLLs if `.original` backup exists (OptiScaler placed them)
- `EnsureStagingAsync` skip guard: `if (IsStagingReady && !HasUpdate) return;`
- **OptiScaler versions = `OsVariants`** (`Services/OsVariants.cs`): built-ins Stable / Nightly / DlssNr / F5 plus custom builds `Custom:<slug>`. Use `OsVariants.All()` / `Label` / `FromLabel` / `IsKnown` / `IsOs10` / `NeedsNrDll` instead of new string lists or `isNightly || isDlssNrOrF5` checks; INI template suffix via `OptiScalerService.IniSuffix`. **Custom builds** (`OsCustomBuildService`, Settings card `SettingsHandler.OsCustomBuilds.cs`): user-added from a link (any host), zip / 7z / rar, folder or bare `OptiScaler.dll`; stored in `%LocalAppData%\RHI\optiscaler-custom\<slug>\build\` + `rhi_custom_build.json` (the folders are the list). Only check: an `OptiScaler.dll` within 3 folders (shallowest wins); a DLL whose ProductName isn't OptiScaler is added with a note. Never updated: no update check, skipped by Update All, `HasUpdate*` untouched; Replace + offer to redeploy (`UpdateAsync`). Install / update use the build folder as staging; a removed build aborts install with a message, and the Default version falls back to Stable. Plan: `docs/custom-optiscaler-builds-plan.md`. Archives dropped on RHI (file or link, both drop paths end in `ProcessDroppedArchive`) with an `OptiScaler.dll` and no RenoDX addon offer to add a custom build. **Recommended forks** (`OsForkService`, manifest `osForks`, variant `Fork:<id>`): listed releases newest by publish date (prereleases included by default), asset by `assetPattern` or `ScoreAsset` ranking; staged in `optiscaler-forks\<id>\build\` + `fork.json` (definition kept, so it works offline); install / update call `EnsureStagedAsync` (downloads when out of date), the update check calls `CheckForUpdateAsync` for forks installed games use. Definitions load next to `FeatureFlags.ApplyManifest` in all three init paths + the 4 h refresh; `SettingsViewModel` keeps a saved `Fork:` / `Custom:` default even before the manifest loads. 
- **Release pins and Check now** (OptiScaler ⚙, `MainWindow.Events.Components.OptiScaler.Release.cs`): `OsReleaseService` lists GitHub releases for Stable / DLSS NR (prefers the `-rtx40-mfg` zip, as the built-in download does) / F5 / forks. A per-game pin reuses `OsNightlyBuild` (one value per game: a nightly date for Nightly, a release tag otherwise; 8-digit values are never release pins; the ⚙ clears it when the version changes). Pinned installs stage into `optiscaler-pinned` via `EnsurePinnedAsync` and set `isPinned` in Install/Update (fixed dir, no update flags); the update check skips pinned games (`GetOsPinnedRelease`). The version line shows installed vs latest; Check now invalidates the ETag entry, refetches, sets the service's own update flag and marks the card; Update calls `InstallOsButton_Click` with the card in the button's Tag.
- **NR runtime for DLSS NR / F5**: install (5b) and update (4e) deploy `nvngx_dlssnr.dll` through `GetNrRuntimeForAsync`: the ⚙'s NR Runtime pick (`OptiScalerService.NrRuntimeProvider`, set by `MainViewModel` to `GetOsNrRuntime`), else the newest. Update skips it when `rhi_install.txt` has `NrMethod` (the Neural Rendering section owns the file). Variant lists that must include F5: version fallback switches (BuildCards / CacheLoad), startup staging (both init paths), the post-install Streamline step (`InstallEventHandler`). Plan to replace these lists: `docs/custom-optiscaler-builds-plan.md`.
- **Install checks for a newer release first** (`InstallAsync` step 3 calls the variant's `CheckFor*UpdateAsync`, ETag-cached; skipped for a pinned nightly build). The periodic check only covers variants an installed game uses, so without this a fresh install / reinstall deployed a stale staged build forever (issue #163, F5 stuck on 0.1.29).
- **Old nightly builds** (`Settings.OsNightlyCleanup`, Settings › Components › OptiScaler, default off; row built by `SettingsHandler.OsDefaultVariant.cs`): builds are staged in `%LocalAppData%\RHI\optiscaler-nightly\yyyyMMdd\` (200-300 MB each). `OptiScalerService.RemoveOldNightlyBuilds(keep)` deletes every dated folder except the newest complete one (has `OptiScaler.dll`), the pinned builds (`GameNameService.OsNightlyBuild` values, incl. Control UE's 20261004) and folders without `OptiScaler.dll` (download still unpacking). Runs after a new build stages (`NightlyCleanupKeepProvider`, set by `MainViewModel`), at startup in both init paths, and when the setting is turned on. Installs use `rhi_install.txt` for uninstall, so deleted builds aren't needed later.
- **Plugins folder depends on the build**: OptiScaler 10 builds (nightly, F5, DLSS NR) have an `OptiScaler\` subfolder and load plugins (`*.asi`, same-name DLLs) from `OptiScaler\plugins`; 0.9 stable (on hiatus until 0.9.5) loads from `<game>\plugins`. Always use `OptiScalerService.GetPluginsDir(gameDir)`. `LoadAsiPlugins=true` is enforced on install and ini deploy.
- **Presets** (top of the OptiScaler cog, all variants; `MainWindow.Events.Components.OptiScaler.Presets.cs`): ready-made presets from `optiscaler_presets.json` (repo root, live data like `dlss_manifest.json`: pushing to main deploys it) via `OsPresetService.ManifestPresets` (fetched in both init paths + the 4 h refresh, cached in `%LocalAppData%\RHI\optiscaler_presets.json`, built-in copies in `OsPresetService.BuiltInPresets` as fallback; keep the two in sync). Entries are `OsPreset` fields in camelCase (null = leave alone) plus `id`, `description`, `streamlineVersion` (`latest` = first of `StreamlineVersions`) and `installUniversalMfg` (`MainViewModel.EnsureUniversalMfgForPresetAsync`: plugin with OptiScaler 10, else first free of version/winmm/dinput8). `installAnrFg` (closed source: first install shows `DetailPanelBuilder.ShowClosedSourceNoticeAsync` (static), setting `AnrFgClosedSourceDismissed`; the cog is hidden first because only one dialog can be open, the download then runs in a progress dialog and the cog reopens; `MainViewModel.EnsureAnrFgForPresetAsync` → `AnrFgService`: stages the newest apex-compute/ANR `*-addon.zip`, SHA256-checked, into `%LocalAppData%\RHI\anr-fg`, copies it to `<Opti folder>\custom\Apex Neural Rendering FG\` keeping `nr_fg.ini`; needs a build that loads custom DLSSG providers, upstream commit 941ce6a1, not in 0.9.4: checked by `OptiScalerService.SupportsCustomFgProviders`, which looks for the "Custom DLSSG" log text in the installed DLL, so forks and custom builds on a recent Nightly work; the 7 Nov F5 v0.1.37.2 doesn't have it). The ANR FG preset is hidden unless manifest `featureFlags.anrFg` is true (`FeatureFlags.AnrFg`, dev unlock.txt always sees it; still shown in games where ANR FG is installed) Its patch notes say it's locked until the source is public; drop that line when the flag goes on. Presets that use fields older RHI versions don't know go in the `presetsV2` array (older versions only read `presets`, so they never show them); `Parse` appends `presetsV2` after `presets`. OptiScaler updates keep both `OptiScaler\plugins` and `OptiScaler\custom` (`DeleteDirKeepingPlugins`). FGNvngxReplacement is written when `OptiScalerService.UsesNvngxReplacement` (FGOutput=dlssg or FGInput=nvngxfg); the cog's FG Nvngx Override lists custom providers by folder name (`FindCustomFgProviders`). Applied by the same `ApplyOsPreset` as the 4 user slots (`os_presets.json`, one dropdown). The ticked preset = `IsOsPresetActive` (FG fields only).
- **DXVK coexistence** (install step 4b): a DXVK DLL with OptiScaler's name moves, before the files are copied, to the folder the build being installed loads same-name DLLs from (`OptiScalerService.PluginsDirForBuild`): `OptiScaler\plugins` on 10 builds, `<game>\plugins` on 0.9 (never create `OptiScaler\` for 0.9: it marks the game as a 10 host). Evidence for 0.9.4: its DLL has no `OptiScaler\` path string, only `plugins`, and logs "OptiScaler working as dxgi.dll, original dll loaded from plugin folder" (also d3d12 / winmm / version / dbghelp / wininet / winhttp); its ini says `OptiDllPath` default `.\` and plugins "under OptiDllPath" (the `.\OptiScaler\plugins\` example in that same comment is copied from 10). A same-name file there that isn't DXVK is never replaced (`DxvkService.CanWritePluginCopy`): the move is skipped and step 5 saves DXVK's DLL as the `.original`. A failed install before OptiScaler's record is saved moves it back and restores the DXVK record (`UndoDxvkCoexistMove`, both folders). DXVK's own install / update / uninstall / preflight / detection, OptiScaler uninstall (4c, moving it back) and the folder mover use `OptiScalerService.GetPluginsDir` to place it and `DxvkService.FindPluginCopy` to find it (installed build's folder first, then the other; a root `plugins\` copy must be a DXVK file). Version changes go through uninstall + install, so the copy follows. Not handled: a fork / pinned release whose update switches between 0.9 and 10 layouts, and games where an older RHI already created `OptiScaler\plugins` for a 0.9 install (GetPluginsDir still treats them as 10 hosts).
- **No `ConfigureAwait(false)` in `InstallAsync` / `UpdateAsync`**: both set card properties at the end, and the card's PropertyChanged rebuilds UI. After `.ConfigureAwait(false)` on an await that really goes to the network, the rest runs on a thread-pool thread and the card update throws (a WinUI COMException with an empty message). ### Pushing component updates into game folders
- `EnsureStagingAsync()` sets `HasUpdate = false` after a successful download. Never gate the "copy into games" step on `HasUpdate` after staging has run — it is always false by then (this broke RTX 40 MFG, NR Cost Scaler and DLSSG 20/30 startup deploys). Capture the flag before staging, or better, compare the game copy with staging.
- **Never clear staging before the replacement download.** Install / update download a new build while the old one stays staged; the `Ensure*StagingAsync` methods replace it only after the new files are fully written (`FileHelper.WriteStreamAtomicAsync`: temp file, length check, move; OptiScaler `ReplaceStagedBuild`: copy to `<staging>.new`, remove version.txt, swap). A failed download then still installs the staged build instead of nothing (Nov 2026: OptiScaler F5 install cleared staging, the download found no asset, the install failed). The stable OptiScaler staging folder also holds RHI's `saved-inis` and `ini-reference` (the old `ClearStaging` on every update deleted them): `OptiScalerService.RhiStagingDataDirs`. A new stable build removes the old build's subfolders except those, and the install / update / record / staging-scan loops skip them (older installs copied them into games; `RemoveCopiedRhiDataDirs` deletes those copies when `rhi_install.txt` lists them).
- Prefer content/size+mtime comparison over "update happened this session": a copy that fails (game running) is then retried on the next launch. `File.Copy` preserves the source's modified time, so size + `LastWriteTimeUtc` identifies an outdated RHI-made copy cheaply.
- Never re-create a tracked file that no longer exists in the game folder — the user removed it.
- Components that copy addons directly must call `AddonPackService.TrackAddonDeployment` / `UntrackAddonDeployment`.

## Backup and restore (v2.9.5, plan `docs/backup-restore-plan.md`)
- `.rhibackup` = zip (`Services/BackupArchive.cs`, pure, tests `BackupTests`): `backup.json` (`BackupManifest`: per game name, store, path, installed components `BackupComponents`, config files), `rhi/<path>` = RHI data from the whitelist `DataFiles` / `DataFolders` (settings.json, presets, `dldsr-captures.json`, `inis\`, `Custom\`, `optiscaler\saved-inis\`, `optiscaler-custom\`, `artwork\custom\`, …) plus only the user parts of `game_library.json` (`GameLibraryKeys`: ManualGames, Hidden, Favourites, DXVK toggles), `games/<n>/` = config files (`GameConfigNames` + the preset reshade.ini's `PresetPath` points at, 1 MB cap), `nvidia.json` = `DlssPresetService.ExportProfiles`. **Never** install records (they'd claim installs that aren't on disk), caches, downloads, `github_api.txt` / API keys, `unlock*.txt`. **A new user-data file or folder in `%LocalAppData%\RHI` must be added to `DataFiles` / `DataFolders`**, or it's lost on a reformat.
