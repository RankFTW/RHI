### [x] A4. Download the Luma wiki page once, not twice at the same moment

**Done 26 Nov 2026** (`3fb987e7`). Log check: `60 wiki + 62 releases = 82 merged`, `Parsed 136 UE game entries`.

**File:** `RenoDXCommander/Services/LumaService.cs`: `FetchCompletedModsAsync` and `FetchGenericUeTableAsync` both call `PageFetch.GetStringAsync(_http, WikiUrl)`, and both are started together at launch and on Refresh.

**Change:** add a helper and call it from both places instead of `PageFetch.GetStringAsync(_http, WikiUrl)`:

```csharp
private readonly object _wikiLock = new();
private Task<string>? _wikiHtmlTask;
private DateTime _wikiHtmlAtUtc;

// Both wiki readers start together: share one download. Reused for 10 s only, so Refresh and the hourly check fetch fresh.
private Task<string> GetWikiHtmlAsync()
{
    lock (_wikiLock)
    {
        if (_wikiHtmlTask != null && !_wikiHtmlTask.IsFaulted && !_wikiHtmlTask.IsCanceled
            && (!_wikiHtmlTask.IsCompleted || DateTime.UtcNow - _wikiHtmlAtUtc < TimeSpan.FromSeconds(10)))

        _wikiHtmlAtUtc = DateTime.UtcNow;
        return _wikiHtmlTask = PageFetch.GetStringAsync(_http, WikiUrl);
    }
}
```

### [x] B3. Addon tracker: stop the lost-update race and the 102 rewrites per launch

**Done 26 Nov 2026** (`2b7e6e17`). Log check: second launch ran 102 deployments and `addon_deployments.json` kept its modified time and contents. Enabling / disabling a global addon was not tried.

**File:** `Services/AddonPackService.cs`, `DeployAddonsForGame`.

**Problem:**
- **Measured:** it runs for 102 games in parallel at launch, and each run rewrites the whole of `addon_deployments.json` even when nothing changed.
- **Read:** `LoadDeployments()` and `SaveDeployments()` each take the lock on their own. Two games that change their entries in the same pass can overwrite each other, because each saves the copy it loaded earlier. A lost entry means RHI later leaves that game's addon files behind, since it only removes files it has on record.

**Change:**

1. Right after `var deployments = LoadDeployments();` take a text snapshot of every entry:
   ```csharp
   static string Sig(HashSet<string> files) => string.Join(",", files.OrderBy(f => f, StringComparer.OrdinalIgnoreCase));
   var before = deployments.ToDictionary(kv => kv.Key, kv => Sig(kv.Value), StringComparer.OrdinalIgnoreCase);
   ```
2. Replace the final `SaveDeployments(deployments);` with:
   ```csharp
   // Write only this call's own changes onto the newest file, so parallel games can't overwrite each other.
   var changedKeys = deployments.Keys.Union(before.Keys, StringComparer.OrdinalIgnoreCase)
       .Where(k => (deployments.TryGetValue(k, out var now) && now.Count > 0 ? Sig(now) : "")
                != (before.TryGetValue(k, out var was) ? was : ""))
       .ToList();
   if (changedKeys.Count > 0)
   {
       lock (_deploymentsLock)
       {
           var fresh = LoadDeployments();
           foreach (var k in changedKeys)
           {
               if (deployments.TryGetValue(k, out var set) && set.Count > 0) fresh[k] = set;
               else fresh.Remove(k);
           }
           SaveDeployments(fresh);
       }
   }
   ```

**Notes:**
- `_deploymentsLock` is an ordinary `lock`, so taking it around `LoadDeployments` / `SaveDeployments` (which take it too) is safe.
- An empty set counts the same as a missing key, because `SaveDeployments` already drops empty sets.
- Keep the file work (copies, stale removal) outside the lock, as now.

**Check:**
- Launch twice with no addon changes: `addon_deployments.json` keeps its modified time.
- Enable a new global addon, restart: every ReShade game's folder is listed with it. Disable it, restart: it is removed from every game.

## Looked at and not recommended

- **ReadyToRun, trimming, single-file compression.** ReadyToRun makes the exe bigger and publish slower for a start that already takes about 1 s to cards. Trimming is unsafe with WinUI 3, reflection-based JSON, NvAPIWrapper and ClrMD. Compression needs self-contained and slows startup.
- **A buffered log writer.** The log already writes in batches off the caller's thread, and crash lines are written straight to disk. Buffering more would risk losing the last lines before a crash.
- **Moving the Extras / Experimental file checks off the UI thread.** A build takes 26 to 37 ms here. The panel code depends on sections being built in order, and the knowledge doc's UI Freeze section says not to change that.
- **Skipping the second `AddonPackService.EnsureLatestAsync` call at launch.** It resets the pack list before the manifest overrides are applied, so it has to stay.
- **Skipping the Extras rebuild after `NotifyAll`.** It saves about 85 ms, but several flows rely on it to refresh their rows.
- **Timers, images, brushes, the overlay, event subscriptions.** All checked; nothing to fix.
