# UI Patterns & Knowledge

## Panel Architecture
- Overrides panel: `DetailPanelBuilder.Overrides` split across partials (`.RsChannel.cs`, `.ShadersAddons.cs`, `.Dxvk.cs`, `.NvidiaProfile.cs`, `.DriverSettings.cs`, `.Dlss.cs`)
- Code-behind builders (NOT XAML templates). `DetailPanelBuilder` receives services via constructor injection (11 services).
- `BuildOverridesPanel()` fills `OverridesPanel`, the DLSS / Driver Settings panels (`.Overrides.NvidiaProfile.cs`, `.Overrides.DriverSettings.cs`) and `ManagementPanel`. Neural Rendering is built by `DetailPanelBuilder.NeuralRendering*.cs`, Extras by `DetailPanelBuilder.Extras*.cs`.

## Detail Panel Section Layout
There is only one layout (Detail). `DetailPanel` StackPanel = 2 header Grids (game info) at index 0–1, then 7 section Borders. Default order (`SettingsViewModel.DefaultSectionOrder`, key → container → panel):
1. `Components` → `DetailComponentSection` — component install rows (in XAML)
2. `GameOverrides` → `OverridesContainer` → `OverridesPanel`
3. `NeuralRendering` → `NeuralRenderingContainer` → `NeuralRenderingPanel`
4. `NvidiaProfileDlss` → `NvidiaProfileDlssContainer` → `NvidiaProfileDlssPanel` ("DLSS / Streamline")
5. `NvidiaProfileDriver` → `NvidiaProfileDriverContainer` → `NvidiaProfileDriverPanel` ("Driver Settings"; driver version is the first summary item)
6. `Management` → `ManagementContainer` → `ManagementPanel` (Change install folder, Reset / Remove game, Reset Overrides, Copy Report)
7. `Extras` → `ExtrasContainer` → `ExtrasPanel` (ASI Loader, OptiScaler, MFG unlocks, DXVK, dgVoodoo2)

- `NvidiaProfileContainer` is a legacy Border kept collapsed for migration; never show it. Old setting key `NvidiaProfile` migrates to `NvidiaProfileDlss` + `NvidiaProfileDriver`.
- Every section collapses (heading click, `CollapsedDetailSections`) and reorders (≡ drag handle, `DetailSectionOrder`); both persist in settings. `ApplySectionOrder()` must run after all sections are populated and visible. Collapsed headers show a summary (`MakeSectionSummaryInlines`).
- **Layout host** (`DetailLayoutHost.cs`, `DetailPanelBuilder.Layout`): owns the section key → container map (`GetContainer` / `GetKey`), the order (`ApplySectionOrder` / `SaveSectionOrder`) and collapse state (`IsCollapsed` / `SetCollapsed`, which saves). Section builders must ask the host, never read or write `CollapsedDetailSections` / `DetailSectionOrder` directly, so every layout (`docs/layouts-plan-2.9.0.md`) arranges the same containers. Layout = `Settings.MainLayout` (`Classic` | `Tabs`), chosen with the top bar switch (`MainWindow.TabsChrome.cs`, `SetMainLayout`; there is no Settings option); a change calls `MainWindow.ApplyMainLayout()` (one rebuild of the shown game). Every section builder calls `Layout.RegisterHeader(key, headerRow)` after building its header row (Tabs hides headers). Code that shows a section outside the selection path uses `Layout.ShowSection(key)`, never `container.Visibility = Visible` (Tabs would show it under the wrong tab). **Tabs**: tab strip inserted at DetailPanel index 2 (sections start at 3; the Classic ≡ drag code assumes 2, fine because Tabs hides the handles), tabs come in a fixed order (`FixedTabOrder`), not Classic's `DetailSectionOrder`; `IsCollapsed` is always false, `ApplySectionOrder` shows only `Settings.DetailSelectedTab`; switching tabs only changes visibility, never rebuilds. **Overview tab** (Tabs only, `DetailLayoutHost.Overview.cs`): replaces the Components tab (Components container stays built and updated but hidden). One card per Components row (`MainWindow.ComponentRows`, `ComponentRowRef`): cards hold no rules, they copy the hidden row's label, status, button text/colours/enabled state and Info/⚙/✕ visibility after `UpdateDetailComponentRows` (`Layout.RefreshOverviewCards()`) and `UpdateDetailProgressRows` (`RefreshOverviewProgress()`), and their buttons call the row's own handlers with the **row's** button as sender (the Info dialog picks the component by the button's `Name`). New component rows: add them to `ComponentRows`. At a glance tiles copy each section's header summary (TextBlocks after index 3 in the registered header row); summaries filled in later, or rebuilt on their own, must call `Layout.SummaryChanged()` (DLSS, Driver and Neural Rendering after their background builds; `BuildExtrasSection` at its end, which also covers Game Overrides and Management because Extras is built last in `BuildOverridesPanel`). Spotlight's Tune tiles use the same call.
- New sections: add a key to `DefaultSectionOrder`, a container in `DetailLayoutHost.GetContainer`, and a summary.

## Tabs layout (mockup A, v2.9.0)
- Must look and behave like `docs/mockups/layouts-2.9.0/Main.dc.html`. Colours, sizes and control factories: `TabsTheme.cs` (tokens also in `docs/layouts-plan-2.9.0.md`). Grids use `Controls/AutoFitGrid` (CSS `repeat(auto-fit, minmax(N, 1fr))`, items stretch when fewer than columns).
- **Nothing is copied.** Section builders create every control as in Classic; when `Layout.IsTabs` they hand the finished, not-yet-shown content to `DetailLayoutHost.Sections.cs` (`ArrangeOverrides`, `ArrangeDlss`, `ArrangeDriver`, `ArrangeNeuralRendering`, `ArrangeExtras`; Management builds its tiles itself), which moves those same controls into the mockup arrangement and calls `TabsTheme.Restyle`. Arranging before the content is shown adds no layout passes (freeze history). A setting added to a builder appears in both layouts; if a builder's shape changes, the arrangers fall back to untitled cards rather than dropping controls.
- Overview cards (`DetailLayoutHost.Overview.cs`), the game header (`DetailLayoutHost.Header.cs`) and the top bar / sidebar / footer (`MainWindow.TabsChrome.cs`; the top bar and the sidebar (segmented main filter, Filters button) are used in every layout, Classic too, while the footer restyles only in Tabs / Spotlight) copy state from the hidden Classic controls and call their handlers with the Classic control as sender (`MainWindow.ComponentRows.cs`, `MainWindow.HeaderActions.cs`). The Classic header rows and Components section stay in the window (hidden), so their buttons keep a XamlRoot.
- Layout switches happen on the Settings page, where the DLSS / Driver / Neural Rendering background builds skip themselves (freeze guard), so `ApplyMainLayout` only flags `_layoutRebuildPending` there and `UpdatePageVisibility` rebuilds the game page when it's shown again.
- Tabs page: full width (32 px padding, cap 1600) via `MainWindow.UpdateDetailPanelWidth()`; Classic keeps 850. Section containers lose their card frame in Tabs (`ApplyContainerChrome`).
- **WinUI pitfalls hit here:** (1) moving controls: empty the old parent (`Children.Clear()`) before adding them elsewhere; `FrameworkElement.Parent` isn't reliable for code-built trees ("No installed components were detected"). (2) Setting a `ResourceDictionary` key that already exists throws a COMException with no message: use `TabsTheme.SetResource` (removes first). (3) Button hover colours are read when the template loads, so a button whose look changes is replaced, not restyled.
- **Dev screenshot hook** (`MainWindow.DevScreenshot.cs`, needs `unlock.txt`): write `%LocalAppData%\RHI\rhi_screenshot_requested` with an output .png path, optionally `tab=<key>`, `game=<name>`, `layout=Classic|Tabs`, `target=detail`, `wait=<ms>`; RHI renders itself with `RenderTargetBitmap`. Needed because a normal process can't capture RHI running in Admin Mode.

## Spotlight layout (mockup D, v2.9.0)
- `MainLayout.Spotlight` builds on Tabs: `Layout.IsTabs` is true for both (Tabs look, `Arrange*` section layouts, Tabs top bar / sidebar restyle / footer); `Layout.IsSpotlight` adds the rest. Plan and decisions: `docs/layouts-plan-2.9.0.md` step 4.
- Page (`DetailLayoutHost.Spotlight.cs`): `ApplyHeroMode` moves the Tabs header into a hero Border over the Steam artwork (title 44) and puts the page body ("What's installed" `StatusTile`s copied from `ComponentRows`, "Tune this game" = `MakeGlanceTile`s) in `_tabChrome` instead of the tab strip. No section shows on the page.
- **Slide-in panel**: `SelectTab(key)` in Spotlight calls `OpenPanel(key)`, which **moves the section's container** out of `DetailPanel` into an overlay added to `GameViewPanel` (scrim + right-hand sheet, `PaneThemeTransition`); `ReturnPanelContent` puts it back (appended; `ApplySectionOrder` reorders). Overview (`OverviewKey`) shows the component cards with At a glance hidden. `ShowSection` / `ApplySpotlightSelection` show only the panel's container. Leaving Spotlight closes the panel (`ApplySectionOrder`).
- Window (`MainWindow.SpotlightChrome.cs`, called from `ApplyTabsChrome` after the Tabs chrome): `GameViewPanel` gets two rows; the sidebar spans the top row (search + switch left, Filters + counts right in row 0 of its grid), the content column the bottom row. `GameList` is collapsed and a horizontal `ListView` shelf with the same `ItemsSource` (`DisplayedGames`) takes its grid row; shelf selection sets `GameList.SelectedItem`, so the normal selection / debounce / rebuild path runs. Tiles are built in `ContainerContentChanging` (no bindings); right-click uses `GameRow_RightTapped` (card in `Tag`); the wheel scrolls sideways.
- **Covers at top / bottom** (`Settings.SpotlightShelfAtBottom`, button `_shelfPositionBtn` in `_countsGrid` column 1 beside Filters, Spotlight only): `ApplySpotlightShelfPosition` swaps GameViewPanel's row heights (strip Auto / page * or the reverse) and mirrors the strip at the bottom (list grid rows: covers 0, search + counts 2, filter chips 3; on top: search + counts 0, filter chips 1, covers 3; the collection chips sit in `_countsGrid`, left of Filters). Leaving Spotlight restores search 0 / chips 1 / counts 2. Controller: fixed controls below the scroller are zone 2 in `CollectPadTargets` (sorted after the page), and "covers → Launch" is Down on top only; at the bottom Up from the covers is a normal row move (the last Tune row above).
- **Resizing by drag** (`Controls/ResizeGrip.cs`: a strip with the up/down cursor; distances measured against `MainWindow.LayoutRoot`, the root inside the interface scaling, so they're in layout units; double-click = reset). Banner: grip on the hero's bottom edge, `Settings.SpotlightHeroHeight` (0 = automatic: height follows width at the Steam hero art shape 3840x1240, clamped 340-500; dragged 200-900). Covers: grip on the strip's edge facing the page (`PlaceCoverGrip`, top edge when the covers are at the bottom), `Settings.SpotlightCoverScale` 0.6-2.0 (1 = 120x180); `TileWidth` / `CoverHeight` are properties in `MainWindow.SpotlightCoverSize.cs`; covers are re-decoded only when a drag ends (80 px decode steps). The banner art is an `ImageBrush` (AlignmentX Center) on a Border, not an `Image`: an `Image` with UniformToFill kept its left side when the banner was dragged tall.
- Artwork: `SteamArtworkService` (AppID via `DetailPanelBuilder.ResolveCommunityAppId`), cache `%LocalAppData%\RHI\artwork\{appid}\hero.jpg|cover.jpg`, misses remembered 7 days (`*.miss`), 4 parallel downloads, only requested while Spotlight is on. Covers are decoded at 240 px and cached per path. **Custom art** (game menu › Artwork, Spotlight only; the hero's right-click opens the same menu): `SetCustom` copies the image to `artwork\custom\{GameName|Store, sanitised + hash}\{cover|hero}-{ticks}.ext` (new name per change so cached BitmapImages aren't reused) and wins over Steam art; `ClearCustom` = Use Steam cover/banner. Not a per-game override in settings, so it isn't migrated on rename.
- **Steam achievements** (`DetailLayoutHost.Achievements.cs`, `Services/SteamAchievementService.cs`; opt-in `Settings.SteamAchievements`, default off; Settings section `Section:Achievements` built in C# by `SettingsHandler.Achievements.cs`, inserted before Tools and before the nav is built so it gets a jump button; later stores get their own rows there): a strip in the header's right column under the HDR / Resolution toggles (`_achSlot`, width follows `_hToggles` so long names trim instead of widening the column), shown only in Spotlight with the setting on and a schema file for the game's AppID (`ResolveCommunityAppId`). Strip = "You've unlocked X/Y (Z%)", bar, latest unlock, recent unlock icons + "+N"; a `WrapTile` Button (focusable) that opens `OpenPanel(AchievementsKey)`, a built panel, not a section container (`ReturnPanelContent` just drops it). Panel: summary card, search, Unlocked (newest first) then Locked (game order), rows added in chunks at Low priority; hidden locked ones masked. Data: binary KeyValues (`SteamBinaryKv`: 0 subtree, 1 string, 2/4/6 int32, 3 float, 7 uint64, 8/11 end); unlocked = the schema block's `bits` key as an index into the stats file's `cache/<block>/data` int32 bitfield (cast to uint, don't sign-extend), times in `AchievementTimes`. Account = registry `ActiveProcess\ActiveUser`, else `MostRecent` in `loginusers.vdf`. The set is cached by both files' write times + Steam language; a `FileSystemWatcher` on `appcache\stats` (`UserGameStats*.bin`, 1.5 s debounce) reloads the shown game. Icon names must be a 40-hex Steam hash (used in a path). Tests: `SteamAchievementTests`. **Xbox** (`Settings.XboxAchievements`, own card in the same section; `Services/XboxAchievementService.cs`, `Services/WinSqlite.cs`): shared records `Achievement` / `AchievementSet(Store, GameId, Items)` in `Services/Achievements.cs`. Used for `Source == "Xbox"` cards (falls back to Steam's cache when the game also has an AppID). Reads the Xbox app's `%LocalAppData%\Packages\Microsoft.GamingApp_8wekyb3d8bbwe\LocalState\AsyncCache.db` read-only through Windows' own `winsqlite3.dll` (copy to temp if the live file can't be opened). Table `AsyncCache(scope, scopeVersion, key, value JSON)`: `achievements_<xuid>_<titleId>` = the list; owner XUID = the one with the most lists (friends' lists are cached too; XUIDs are 16 digits, title ids up to 10). Title id: PFN from `DetectedGame.XboxAumid` → `product_altid_pfn` → product id → `product_summary` alternateIds XBOXTITLEID (or reverse `product_altid_titleid`), else `titleInfo_` name match. Secret ones carry real text: masked like Steam's hidden ones. Icons are 16:9 1920x1080 and shown at 16:9 (`AchIconWidth`; a square crop showed only a sliver of the emblem): downloaded with `h=160&format=png`, cached in `artwork\xbox\{titleId}\ach\` by SHA1 of URL + size. Watcher on `AsyncCache.db*`; the list is compared before redrawing because the app rewrites the db for many reasons. The cache only has games the Xbox app has shown. Tests: `XboxAchievementTests`.
- Dev screenshot hook: `tab=none` closes the panel; any other `tab=` opens it in Spotlight. Its one-shot timer is held in a field (a local `DispatcherQueueTimer` can be garbage-collected before it fires: that silently broke screenshots). `pad=Down,Select,Back` runs controller actions (one per 600 ms, focus logged) before the screenshot; it presses buttons for real, so never script A onto install/remove buttons.
- **Controller support** (`MainWindow.Controller.cs`, `Services/ControllerInput.cs`, `Services/PlayStationPad.cs`, `DetailLayoutHost.Controller.cs`; PlayStation pads (DS4 054C:05C4/09CC/0BA0, DualSense 0CE6, Edge 0DF2) are read natively from HID input reports on a background thread (shared read-only handle; `PlayStationReport.Parse` handles USB 0x01, DS4 BT 0x01/0x11, DualSense BT 0x01 simple/0x31; USB = 64-byte reports) into XInput-style `PadState`; XInput wins when both are present (DS4Windows / Steam virtual pads), and the hints show PlayStation names; Steam Controllers are read the same way (`Services/SteamControllerPad.cs`, Valve 28DE: new "Triton" 1302 USB / 1303 BT / 1304-1305 dongles, report ids 0x42/0x45/0x47; original 1101/1102 USB / 1142 dongle, ValveInReport type 1/7; original BT 1105/1106 not supported), only vendor-page (>= 0xFF00) interfaces, every dongle slot interface read on its own thread, state from the one that reported last; RHI never writes to it (no lizard-mode change, Steam keeps control); Xbox names in the hints; shared HID calls in `Services/HidNative.cs`; Spotlight only, setting `ControllerSupport`, row added under Drop Helper by `SettingsHandler.Controller.cs`): XInput polled on a UI timer (16 ms with a pad, 250 ms otherwise, empty slots rescanned every 2 s) only while RHI is the foreground window; `ControllerPoller.Reset` ignores buttons held when RHI becomes active. Focus moves with `FocusManager.FindNextElement` + `TryFocusAsync(FocusState.Keyboard)` (focus outline, bring-into-view); special cases: shelf left/right = previous/next game, shelf Down = Launch, Launch Up = shelf, shelf Up = the selected All / Installed / … segment (`TabsTheme.SegmentSelectedTag`; segments are Buttons), Down from the search / filter row = the selected cover, panel keeps focus inside `PanelSheet`, footer is skipped, sliders change value. A uses automation peers (Invoke / Toggle / ExpandCollapse; ComboBox opens). Moving on the page and in the panel goes by **rows** (`MainWindow.Controller.Rows.cs`: focusable tab-stop controls grouped by vertical position, zone 0 = fixed chrome, zone 1 = inside the scroll viewer measured in its content so scrolling doesn't reorder; Left/Right stay in the row; entering a row picks Launch / the selected filter segment if the row has one, else the control whose width covers the current control's middle X, else nearest X; there is deliberately no memory of earlier visits: it made Up / Down jump sideways in grids like the DLSS panel); the shelf is one target. Popups are worked **through their controls, never key presses** (`MainWindow.Controller.Popups.cs`): ComboBox items focused by index, A sets `SelectedIndex` + closes, B closes unchanged; MenuFlyout items move with wrap, submenus via ExpandCollapse peer (`_padSubmenus` stack), B closes menu popups / `ContentDialog.Hide()`. In dialogs a control tagged `"PadStart"` is where the controller starts (`FirstInPopup`; What's New tags the selected version, and its version rows are Buttons that show the version on keyboard focus); `WatchForNewPopup` (each poll while the hint bar shows) moves focus into a dialog that appears later, and A with focus behind an open popup moves into it instead of pressing. The right stick in a popup scrolls the biggest ScrollViewer that doesn't hold focus (`PopupScroller`). Dev `pad=` also takes `ScrollDown` / `ScrollUp`. LB/RB: panel = `Layout.StepPanel` (Components + Tune tile order, wraps), Settings = `SettingsHandler.PadJumpSection`. Y (or A on Launch) = `PadLaunch`: toast, 8 s same-game guard, `IsRunning` check, focus returns to the cover when RHI is active again. When a game launched from RHI exits (`MonitorProcessForHdr`, both normal-exit paths), `RefocusAfterGameExit` (`MainWindow.ReturnAfterGame.cs`; Spotlight + `ControllerSupport` only, skipped when hidden to tray) brings RHI to the front: `SetForegroundWindow`, and if Windows refuses (last input went to the game) one Alt tap via `keybd_event` lifts the foreground lock and it retries. No `AttachThreadInput` (removed earlier: hang risk). **Pointer while the pad is in use** (`MainWindow.Controller.Pointer.cs`): `ShowPadHints(true)` shows a transparent, hit-testable shield Border over the root Grid (no hover / tooltips from a resting pointer; popups/dialogs aren't covered) and closes open ToolTips; `ShowPadHints(false)` hides it. The cursor itself stays visible: `ShowCursor(false)` (returned -1) and repeated `SetCursor(null)` from the UI thread, which owns the `DesktopChildSiteBridge` under the pointer, both failed, because WinUI re-sets the arrow. Untried options: WM_SETCURSOR subclass on the bridge, or a blank `ProtectedCursor` (needs a .cur Win32 resource). `PadFocusNext` sets the shield's `IsHitTestVisible = false` for the synchronous `FindNextElement` call in case the search skips covered candidates (unconfirmed: it didn't fix Down from the ⚙ on Settings, which is WinUI's projection search finding nothing below a control far right of the settings column). Opening Settings with the pad (hints showing) focuses the shown section's nav button (`SettingsHandler.PadStartButton`, from `OnSettingsPagePopulated` → `PadFocusSettingsStart`; `FocusHome` uses it too). The shield's arrival raises a PointerMoved without movement, so the hint bar's PointerMoved handler ignores events while the shield is up. **Never set `IsHitTestVisible = false` on the page for this**: `Controller.Rows.cs` skips non-hit-testable nodes, which breaks D-pad navigation. The root Grid is `_uiScaledRoot ?? Content` (`Content` is a scaling Canvas at interface sizes other than 100%). Because the shield swallows PointerMoved, `PadTick` polls `GetCursorPos` (3 px slack) + mouse buttons (`GetAsyncKeyState`) to give the mouse back; losing the foreground restores the pointer but keeps the hints. Touch input is ignored until the mouse moves. Hints (`MainWindow.Controller.Hints.cs`) sit in the footer's centre cell (column 1 of `_footer`'s Grid) and swap with the anti-cheat TextBlock there (`_footerWarning`), compact (10/11 px) to keep the footer one line; they list only what works where focus is and cover nothing. The toast stays in GameViewPanel's parent grid, 14 px above the footer. `PadFocus` sets a blue (`TabsTheme.Accent`) focus visual. LT / RT = 10 games (triggers folded in as unused button bits by `ControllerPoller.WithTriggers`), left stick click = cycle All / Installed / Favourites, with a toast (`CycleMainFilter`); right stick click = next collection, after the last back to All games (`CycleCollection`, toast), or Home (cover) when there are no collections, the panel is open or Settings shows. Controller moves keep the selected cover centred (`CenterShelf`: clamped ChangeView; `_padStepping` skips the shelf's ScrollIntoView and the items panel swallows BringIntoViewRequested for 400 ms). Shelf items have `UseSystemFocusVisuals=False` (the tile's blue ring marks the selection; no white focus box). Spotlight tiles (`TabsTheme.WrapTile`), segmented switches and top bar links (`MakeNavItem`) are Buttons so they can take focus; new clickable Spotlight elements must be focusable controls, not Borders with Tapped.

## RHI overlay (v2.9.3)
- Full-screen RHI page over a game (plan: `docs/rhi-overlay-plan.md`). **An RHI window, never something loaded into the game** (user rejected a ReShade addon). `Overlay/OverlayWindow*.cs` (C#, no XAML): borderless `OverlappedPresenter`, `IsAlwaysOnTop`, `IsShownInSwitchers = false`, moved to the game window's monitor (`rcMonitor`), created on first use then hidden / reused. Backdrop `OverlayBackdrop` = `DesktopAcrylicController` Kind Thin + light tint, root Grid 0x40 dim (the default acrylic hid the game; user wants it see-through).
- Opening: `OverlayHotkeyService` = `RegisterHotKey` on the main hwnd + `SetWindowSubclass` id 2 (id 1 is `ForegroundActivationTarget`); WM_HOTKEY grants foreground. Default Alt + ` (`"192,0,0,1"`, ReShade "vk,ctrl,shift,alt" format). Settings names are `RhiOverlay*` because `OverlayHotkey` is ReShade's key. Controller: `MainWindow.Overlay.cs` has its own timer + `ControllerPoller` (hold View + Menu 500 ms; skipped while RHI's main window is in front, where the Spotlight controller code owns the pad); it shares `_psPad` / `_steamPad` / `StartNativePadScan`. A controller open isn't real input, so `Open` falls back to the Alt-tap trick if `SetForegroundWindow` is refused.
- Games read XInput even when unfocused and Windows can't block that, so the opt-in `RhiOverlayPauseGame` (off by default) freezes the game with `NtSuspendProcess` while the overlay is open (`Overlay/GamePauser.cs`); every close path, `Destroy`, ProcessExit and UnhandledException resume it.
- Game in front: `ForegroundGameResolver` (foreground pid → exe → longest matching `MainWindow.GameProcessSearchRoots`). Closes on deactivation (not forcing the game forward) and when the game window dies.
- One dashboard, no pages (user asked to use the space): section boxes (`_homeBox`, `_gameBox`, `_infoBox`, `_shotBox`, `_achBox`) are moved between three column StackPanels (each in its own ScrollViewer) by `ArrangeDashboard(width)`: >= 1350 layout units = info | screenshots | achievements, >= 860 = info + screenshots | achievements, else one column. Columns are emptied before boxes move (one parent). The screenshot viewer is a layer over the dashboard (`_viewerLayer`). Sections: Home (session from process start time, Steam playtime via `SteamPlaytimeService` reading `userdata\<acct>\config\localconfig.vdf`, else RHI's count; battery), Achievements (same loaders as Spotlight, own larger rows, locked sorted by rarity), Screenshots (`ScreenshotLibraryService`: reshade.ini `[SCREENSHOT] SavePath` → `BuildScreenshotSavePath` → game folder; shared folders filtered by exe-name prefix; delete via `SHFileOperation` to the Recycle Bin), This game (card statuses + DLSS versions), Info (notes, links). LB / RB jump between columns; the right stick scrolls the focused column.
- `GameJournalStore` (`%LocalAppData%\RHI\game_journal.json`): your notes + RHI playtime minutes (a 1-minute UI timer credits the foreground game), keyed `GameName|Store`, migrated in `GameNameService.RenameGame`. Notes are also edited from the game menu (`MainWindow.GameNotes.cs`).
- HDR tile: `Microsoft.Graphics.Display.DisplayInformation.CreateForWindowId(AppWindow.Id).GetAdvancedColorInfo()` for the overlay window (on the game's monitor), not `HdrToggleService.IsHdrEnabled` (false positives). DLSS card: presets / render scale via `DlssPresetService` (`PrimeProfileCache` + getters) in `Task.Run` with a 5 s limit, like the DLSS section (`OverlayWindow.Display.cs`). Live DLSS changes later need an in-game DLL (like OptiScaler) talking to RHI.

## Game collections (v2.9.2)
- User-named lists of games ("Racing"). Data: `Services/GameCollectionStore.cs` (pure, locked, unit tested in `GameCollectionTests`), owned by `GameNameService.Collections` (`GameNameService.Collections.cs`), saved in settings.json as `GameCollections` (ordered `[{Name, Games}]`) + `ActiveCollection` through the debounced `SaveNameMappings`. Members are `"GameName|Store"` keys (`GameKey.FromCard`); `RenameGame` calls `MigrateGameRename`. Games no longer detected stay in their collections (no cleanup). Cards carry no collection flag (pure lookup), so the init paths need nothing.
- Names: trimmed, 1-40 chars, unique ignoring case, not a built-in filter name (All, Installed, Favourites, Hidden, Detected).
- Filtering: `FilterViewModel.ActiveCollectionName` + `CollectionMembers`; `ActivateCollection` resets the main filter to Detected underneath and any `SetFilter` clears the collection. Shows members that are **not hidden** (user decision; unlike Favourites, which shows hidden favourites). Search and custom filters still narrow it. The active collection is restored on launch if it still exists.
- VM: `MainViewModel.Collections.cs` (Create / Rename / Delete / Move / SetCollectionMembership / ActivateCollection, `CollectionsChanged` event). UI: `MainWindow.Collections.cs`: chips (Buttons, `TabsTheme.Apply`, replaced not restyled) in a `Controls.WrapPanel` plus a "+ Collection" chip; right-click (controller X) = Rename / Move left / Move right / Delete (confirm, Cancel default); game menu "Add to collection" submenu of `ToggleMenuFlyoutItem`s (membership follows `IsChecked` via `RegisterPropertyChangedCallback`, so a click and the controller's Toggle peer both work) + "New collection…". Empty collection = a plain message over the list / covers. While a collection is active no segment is selected (`RefreshSidebar` sel = -1).
- **Spotlight Filters button** (`PlaceFiltersButton` in `MainWindow.SpotlightChrome.cs`): in Spotlight `_filtersBtn` moves out of `_countsGrid` into `_searchRowStack` just before `_segmentHost` (icon only, `MakeFiltersLabel(extra, iconOnly)`, count shown when filters are on, stretched to the switch's height); leaving Spotlight puts it back in `_countsGrid` (column 1 while the collections column is still there, shifted by `SetCollectionsColumn`) with its "Filters" label.
- Placement (`PlaceCollectionsHost`): Classic / Tabs = in `_searchRowStack` under the segmented switch; Spotlight = right of the search row, left of the Filters button: `SetCollectionsColumn` inserts an Auto column 0 into `_countsGrid` and shifts Filters / Covers-position / counts one column right (removed again outside Spotlight, where its column spacing would push Filters over); `MaxWidth` 640 so many chips wrap rather than run under the search. Controller: the active chip carries `CollectionSelected` (not `SegmentSelectedTag`); from the covers, away-from-page goes to the active chip, else the selected segment (filter chips row when Filters is open); `PickInRow` prefers the active chip and only a really selected segment.

## Status bar (bottom left)
- `MainWindow.StatusBar.cs` owns `StatusBarText`; never set its Text directly. Priority: `ShowStatusBarMessage(msg, duration)` (one-off notices) > loading/Refresh progress (`StatusText` + `SubStatusText`) > `ViewModel.CurrentActivityText` > offline/error `StatusText` > idle "Last checked: … · Next check in …" (refreshed every 15 s, Minimal mode wording matches the Settings countdown).
- Background work reports itself with `using var activity = BeginActivity("Checking for updates...");` (`MainViewModel.Activity.cs`, thread-safe, overlapping activities show the newest). Used by the background scan, `CheckForUpdatesAsync`, the 4 h periodic refresh and DLSS/Streamline auto-update. New long-running background work should do the same.
- Game and ReShade counts live above the game list (`GameCountText`/`InstalledCountText`), not in the status bar.

## ComboBox Patterns
- Simple strings ("Global", "Stable", "Nightly") — not verbose labels
- Auto-apply on selection change — no "Apply" button
- `comboInitializing` guard flags prevent handler firing during panel construction
- "Select" opens picker dialog; if cancelled, reverts to previous value
- For Vulkan games: warn all Vulkan games affected, apply override to all simultaneously

### ComboBox SelectionChanged fires during construction
Handler can't distinguish init from user click. Use `_suppressSelectionChanged` guard flag set during panel build.

### Panel rebuild clobbers ComboBox state
Override changes call `NotifyAll()` → panel rebuild → ComboBox recreated. Suppress rebuilds during active interaction.

### `IsLegacyVersion()` blocks non-standard items
Returns true for ANY string not null/"Stable"/"Nightly"/"Custom". New RS Channel items must be excluded from this guard.

### ComboBox Re-Selection Pattern (DropDownClosed trick)
WinUI `SelectionChanged` doesn't fire on re-selecting current item. Use `DropDownClosed` handler comparing against LIVE persisted state (not stale local variables). Cancel revert must also query live state.

### comboInit guard must be set false immediately after Add
Set `comboInit = false` right after `Children.Add(combo)` — NOT at end of block. Background merge can rebuild mid-block.

- 150ms `DispatcherTimer` (`_selectionDebounceTimer`) in `GameList_SelectionChanged`

- `PopulateDetailPanel` + `BuildOverridesPanel` are synchronous and heavy

## Admin Mode
- Task Scheduler task "RHI Admin Mode" for UAC-free elevation
- `schtasks /Create /RL HIGHEST /SC ONCE /ST 00:00 /SD 01/01/2000`
- Auto-relaunch: checks on startup, runs task, exits immediately
- `schtasks /Run` can't pass arguments, so the elevated copy never sees the non-elevated one's command line. Hand-off files in `%LocalAppData%\RHI\`: `rhi_start_minimized` (`--minimized`) and `rhi_pending_launch` (UTC time + game name for `--launch` from desktop shortcuts / jump list; ignored after 2 min). Any new startup argument needs the same, or it's silently lost when Admin Mode is on and RHI wasn't running.
- Create/Delete requires one-time UAC (`Verb = "runas"`)

## Drag-Drop (Admin Mode)
- XAML drag-drop (`AllowDrop`) doesn't work elevated (Microsoft bug)
- Fix: `DragAcceptFiles` + `WM_DROPFILES` for Explorer file drops
- `RHI.DropHelper.exe`: non-elevated overlay for Discord URL drops
- `Opacity = 0.01` (NOT TransparencyKey or WS_EX_TRANSPARENT — those block OLE)
- Toggle: `SettingsViewModel.DropHelperEnabled` (default true)

### Two Separate Drop Code Paths
- `Grid_Drop` (non-admin): XAML routing
- `HandleWin32Drop` (admin/WM_DROPFILES): separate routing logic — MUST match
- New file extensions need BOTH paths updated

## HDR Auto-Toggle
- `HdrToggleService.cs` — Win32 CCD API (`DisplayConfigGetDeviceInfo`/`SetDeviceInfo`)
- Per-game UI: button in header, purple when active. Reset Overrides clears to global.
- Process monitoring: polls for game process from `InstallPath`, awaits exit, then disables HDR

## ContentDialog Pitfalls
- **Every dialog gets the navy look automatically**: `DialogService.ShowSafeAsync` / `ShowProgressAsync` call `DialogLook.Apply` (`DialogLook.cs`): `CogDialog.ApplyDialogLook` frame + button styles + blue ticks, a string `Title` becomes `CogDialog.MakeDialogTitle`, content gets colour-only restyling (inputs keep their sizes). Dialogs that call `ApplyDialogLook` themselves are skipped (`RhiDialogLook` resource marker). Don't hand-style new dialogs' colours; don't add icons to titles.
- Default max width ~548px clips wide content. Fix: `dialog.Resources["ContentDialogMaxWidth"] = 900.0;`
- Disabled controls don't show tooltips — place tooltip on visible sibling instead.
- `XamlRoot` can be null during cache phase. Resolve at click time via `(sender as FrameworkElement)?.XamlRoot`.
- **Cannot open nested ContentDialogs**: WinUI 3 only allows one ContentDialog open at a time per XamlRoot. Attempting to show a second dialog while one is already open silently fails. For "Custom..." input inside an existing dialog, use an inline TextBox + Button that shows/hides instead of opening a nested dialog.

## Window State
- `TryRestoreWindowBounds`: clamp to monitor work area (prevents taskbar auto-hide suppression)
- Use `MonitorFromPoint(savedX, savedY)` not `MonitorFromWindow` (window hasn't moved yet at startup)
- Maximized: use `GetWindowPlacement.rcNormalPosition` (preserves correct monitor)

## Installer Shutdown Signal
- Signal file: `%LocalAppData%\RHI\rhi_shutdown_requested`
- 2-second `DispatcherTimer` checks existence. When found: delete, set `_forceClose`, close.

## TextBox Persistence Pitfall
- Settings page text boxes save on Enter **and** on LostFocus (ScreenshotPathBox, AddonWatchFolderBox, PeakNitsBox; handlers in `MainWindow.Events.SettingsInputs.cs`). Hotkey boxes (HotkeyBox, ScreenshotHotkeyBox, UlHotkeyBox) persist the captured key immediately. The "Write ... to all games" buttons still read the box and persist before writing to games; keep that, since a click can run before LostFocus has saved.
- New Settings text boxes must do the same (save on Enter + LostFocus, compare with the saved value first so repeated focus changes don't re-save). Don't rely on an Apply button to persist a typed value.

## WinUI 3 Focus Pitfalls
- No `Window.Focus()` method. Defocus via disable/re-enable: `combo.IsEnabled = false; DispatcherQueue.TryEnqueue(() => combo.IsEnabled = true);`
- Editable ComboBox `SelectionChanged` doesn't fire for typed text until focus loss — use `KeyDown` for Enter.
- Editable ComboBox custom text not visible on init — use non-editable + "Custom..." sentinel + dialog instead.
